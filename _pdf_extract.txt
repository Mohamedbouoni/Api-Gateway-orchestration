Abstract
The rapid adoption of Artificial Intelligence in enterprises has created a need for secure,
scalable, and governable AI service management. TheDeterministic Enterprise AI
Orchestration Platform, developed during an internship at Next Step IT, addresses
this need through a centralized control plane that ensures predictable, secure, and cost-
controlled AI interactions.
Unlike traditional AI platforms, the system does not host models. It authenticates
requests, enforces policies, routes them to the appropriate AI service, and maintains full
observability and auditability. Key features include dynamic plugin discovery and
advanced observability dashboards.
Keywords : AI Orchestration – Kong API Gateway – Keycloak – FastAPI –
OPA – Dynamic Plugin Discovery – Observability.
Résumé
L’adoption rapide de l’Intelligence Artificielle en entreprise a créé un besoin de gestion

Déterministe d’IA d’Entreprise, développée lors d’un stage chez Next Step IT, répond
à ce besoin grâce à un plan de contrôle centralisé qui garantit des interactions prévisibles,
sécurisées et maîtrisées.
Contrairement aux plateformes d’IA traditionnelles, le système n’héberge pas de mod-
èles. Il authentifie les requêtes, applique les politiques, les route vers le service d’IA
approprié et maintient une observabilité ainsi qu’une auditabilité complètes. Ses princi-
pales fonctionnalités incluent ladécouverte dynamique de pluginset destableaux
de bord d’observabilité avancés.

2.4.5 FastAPI

FastAPI [15] powers the core orchestration engine. It was specifically chosen for its native

4.3.3 Software Design
Securing the platform meant we needed a rock-solid authentication system capable of
issuing deterministic, verifiable identities. Rather than cluttering the FastAPI backend
with complex security logic, we externalized all security checks to the API Gateway,
selecting Keycloak as our identity broker.
As shown in Figure 4.1, we built a two-tier edge: the WAF performs CRS threat
detection on all inbound traffic, then Kong applies Correlation-IDs, JWT and tenant
enforcement, and rate limiting. OPA governance runs in FastAPI after Kong forwards
trusted headers. This guarantees that the backend only processes requests that are in-
spected, verified, traceable, and authorized.
Keycloak and OAuth 2.0 PKCE
For identity management, Keycloak handles Single Sign-On (SSO) via the OpenID Con-
nect (OIDC) protocol. It runs atop its own dedicated PostgreSQL database and issues
RS256-signed JSON Web Tokens (JWTs). To maximize security, especially for frontend
client applications, we implemented the OAuth 2.0 Authorization Code flow with Proof
Key for Code Exchange (PKCE).
PKCE introduces a dynamic, per-request secret (thecode_verifier and its hash, the
code_challenge). By strictly enforcing this at the edge, we completely eliminate the risk
of authorization code interception and Cross-Site Request Forgery (CSRF) attacks. Even
if an attacker intercepts the authorization code, it is mathematically useless without the
original verifier.

6.4.3 Zero-Trust Ingress via Cloudflare Tunnels
A critical deployment challenge arose from the network constraints of the hosting envi-

limits, unstable URLs, and lack of custom domain support.
To solve this challenge, we designed aZero-Trust ingress architectureusing Cloud-

How It Works
The Cloudflare Tunnel operates on a fundamentally different networking model than
traditional reverse proxies. Instead of requiring inbound firewall ports to be opened which
would expose the server to direct internet attacks thecloudflared daemon initiates a
secure outbound-onlyconnection from the server to Cloudflare’s global edge network. This
connection is maintained persistently, and all external client traffic is routed through
Cloudflare’s infrastructure before being forwarded to the internal Docker services.
1. A user navigates tohttps://enterprise-ai.online from any device worldwide.
2. Cloudflare’s global CDN receives the request and terminates TLS at the edge.
3. The request is forwarded through the encrypted tunnel to thecloudflared con-
tainer.
4. The cloudflared container routes the request to the internalfrontend service on
port 80.
5. The frontend proxies API requests (/api/*, /ai/*) to the Kong Data Plane inter-
nally.

manual certificate management.
• Edge DDoS Protection: All traffic passes through Cloudflare’s global network,

General Conclusion and Perspectives
The Deterministic Enterprise AI Orchestration Platform provides a production-grade dis-
tributed control plane for secure, governed enterprise AI service management. Following
strict zero-trust architectural principles, the system implements a highly modular, secure,
and observable request/response pipeline designed to prevent data leakage, control API
costs, and enforce organizational compliance. Developed during a five-month internship at
Next Step IT, this project successfully addresses the challenges of uncontrolled shadow
AI usage in modern business environments by introducing a centralized proxy architecture
that intercepts, evaluates, and logs all company-wide interactions with Large Language
Models.
On the edge and identity management layer, we integratedKong GatewayandKey-
cloak to establish a cryptographic security perimeter, validating tokens at the edge and
protecting internal resources from unauthorized access. The backend was developed using
FastAPI, chosen for its asynchronous execution model and low-latency performance in
streaming text token-by-token via Server-Sent Events (SSE). To enforce strict regulatory
compliance and corporate safety rules, we built a governance engine using theOpen
Policy Agent (OPA)and Redis for real-time quota tracking, alongsidePostgreSQL
Row-Level Security (RLS)and Microsoft Presidiofor kernel-level tenant isolation
and automated personally identifiable information (PII) redaction. This comprehensive
security and routing stack was fully containerized usingDocker and deployed on a dedi-
cated server, utilizingCloudflare Tunnelsto establish secure, zero-trust ingress without
exposing inbound ports.
Throughout this internship, I have acquired and consolidated key engineering com-
petencies across security architecture, distributed systems design, and DevOps practices.
Designing a multi-tenant platform with strict separation of layers allowed me to mas-
ter real-world distributed architectures, including cryptographic JWT validation at the
edge, session propagation, and kernel-level database isolation. I gained extensive practical
experience working with cloud-native tooling, configuring enterprise API gateways with
custom Lua extensions, managing authorization policies as code via OPA, and fine-tuning
machine learning models like DistilBERT for real-time intent classification. Additionally,
working within an Agile Scrum framework refined my project management skills, collab-
orative software design practices, and version control workflows.
